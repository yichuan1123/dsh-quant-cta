# 设计说明

## 1. 事件顺序（最重要的约定）

回测高估收益的头号原因是未来函数。本引擎把顺序写死：

```
每个交易日 t：
  ① 开盘：执行「t-1 收盘生成的目标持仓簿」，成交价 = open(t) ± 滑点
  ② 收盘：全部持仓按 close(t) 盯市
  ③ 收盘后：策略用截至 close(t) 的数据决策，生成 t+1 的目标簿
  ④ 结算：记权益快照，判定组合级回撤熔断
```

对应测试：`test_signal_fills_next_open_not_same_close`。

## 2. 期货会计口径

与股票不同，务必分清三件事：

| 概念 | 是否现金流出 | 作用 |
|---|---|---|
| 手续费 | 是 | 开平仓各收一次，平今可能加倍 |
| 保证金 | **否** | 只做「可用资金校验」，不是费用 |
| 浮动盈亏 | 否（除非平仓） | 权益 = 现金 + 浮盈 |

因此：
```
equity = cash + Σ direction × lots × (last_price − avg_price) × multiplier
```
平仓时把该笔浮盈结转进 cash，并生成 ClosedTrade。

**恒等式**（单测守着）：
```
期末权益 − 初始资金 == Σ ClosedTrade.net_pnl
```
它同时守住三件事：手续费不重复计、开仓手续费摊分正确、盯市口径一致。

## 3. 手数换算

```
日风险预算 budget = equity × target_vol / sqrt(252)
每品种预算       = budget × w_i / sqrt(Σ w_j²)
手数             = floor(每品种预算 / (ATR × multiplier))
```

为什么按 `sqrt(Σw²)` 而不是直接按 `w` 归一：等权 n 个品种时若每品种分 `budget/n`，
零相关下组合风险只有 `budget/sqrt(n)`；分 `budget/sqrt(n)` 才能用满预算。

现实里还有两个打折项：手数取整（大合约尤其严重）与品种间相关性，所以**实际波动通常低于目标**。
这不是 bug，是期货粒度与相关性的真实约束。

## 4. 成本模型

- 手续费：`max(费率 × 成交额, 固定费/手)`，平今乘倍率（股指尤其贵 → 这也是坚持日频的理由）
- 滑点：`slip_ticks × tick × multiplier × lots`，买入向上、卖出向下，永不利于策略
- 保证金：`lots × price × multiplier × margin_rate × 1.35`（1.35 模拟期货公司加收）
- 开仓前检查 `equity × 0.85 − margin_used` 是否够，不够就缩减并记拒单

## 5. 风控

| 规则 | 触发点 | 行为 |
|---|---|---|
| 单品种风险上限 | 每次换算手数 | 手数封顶 |
| 名义杠杆上限 | 生成目标簿 | 等比缩减 |
| 组合回撤熔断 | 每日结算 | 停止开新仓（仍可平仓） |
| ATR 止损 | 每日收盘 | 次日开盘平掉该品种 |
| 保证金不足 | 每次开仓 | 缩减手数 + 记拒单 |

## 6. 多策略腿（sleeve）

每条腿独立资金、独立账本、独立归因。总权益 = 各腿之和，组合级熔断对所有腿生效。
这样「按策略归因」是天然的，不需要把 PnL 分摊到策略上。

## 7. 模拟盘为什么是「确定性推进」

日频 CTA 的模拟盘本质是：每天收盘后用真实数据算一次目标，次日开盘按开盘价成交。
在数据固定的前提下，这个过程的账本是**确定性**的——它不会因为随机数而不同。

它的真实价值：
1. 验证数据管道与撮合口径（这是最容易出错的地方）
2. 积累一条**事前生成**的净值轨迹，可与后续回测对照

它拿不到的：真实盘中滑点、流动性冲击、部分成交、断线重连。这些只有实盘有。

## 8. 最优配比（全盘）

**问题**：28 个品种，每个该分多少风险预算？

按金额等分是错的：一跳价值从 10 元（螺纹）到 100 元（原油），等金额会让高波动品种
主导整个组合的风险。按波动率倒数已经把量级拉齐，但没处理相关性。

| 方法 | 解什么 | 适用 |
|---|---|---|
| equal_weight | 1/N | 基准线，用来证明"优化到底有没有用" |
| inverse_vol | 1/σ 归一 | 忽略相关性，快且稳 |
| **risk_parity（默认）** | 等风险贡献 | 不预测收益，只均摊风险；最稳 |
| min_variance | 最小组合方差 | 波动越低越好，但会挤在低波品种上 |
| mean_variance | 均值-方差 | 需要预期收益；样本均值噪声大，默认不推荐 |

**ERC 的解法**：解 min ½wᵀΣw − Σᵢbᵢ·ln wᵢ，一阶条件 wᵢ(Σw)ᵢ = bᵢ（风险贡献相等）。
固定其它分量时对 wᵢ 是一元二次方程，直接求根——坐标下降几十次就收敛到 1e-15。
**注意**：迭代内部不要归一化（会把尺度一起压小，收敛慢一个数量级）。

**协方差收缩**：N=28、T=250 时样本协方差不奇异，但换月/停牌会造成近共线。
用 Ledoit-Wolf 恒等目标收缩 δ* = π/γ（截断到 [0,1]）：Σ̃ = (1−δ)S + δ·m·I。

**约束**：权重非负、单品种上限（默认 15%，防止"全靠螺纹"）、板块上限（默认 35%）。
上限用「封顶 + 缺口回填」的投影，板块上限按比例缩减后回填给未触顶板块。

## 9. 滚动模型（实时更新）

"实时更新"在这里的具体含义：**每 N 个交易日用最近 lookback 根数据重估一次权重**。

- 回测里是 walk-forward：调仓日只用 `asof` 之前的数据，绝不看未来
- paper 里每次推进重算，口径与回测完全一致
- 结果带 version + asof，落盘到 `state/model.json`，并保留最近 20 次历史（看权重漂移）

更新的是**风险预算怎么分**，不是**方向**。方向仍由策略决定——这两件事混在一起
就没法归因"亏损是方向错了还是配比错了"。

## 10. DSH 接入模拟

日频 CTA 的"实时"是每交易日一次，不是每毫秒。所以 DSH 在这里的角色是**调度器 + 观察者**：

```
宿主进程 setInterval(intervalSec)
      │
      ├─ 跑 python -m qcta paper step --json
      │     ├─ 用最新数据重算最优配比（state/model.json）
      │     ├─ 按新权重推进账本（state/paper.json）
      │     └─ 输出本次推进摘要
      └─ 摘要回流：qcta_sim 工具 / GET /api/sim / 面板卡片
```

**刻意不做的**：LLM 不参与交易决策，模拟盘不发任何真实委托。
调度层只负责"按时推进 + 状态回流"，这样出问题时永远能定位到是模型、撮合还是调度。

## 11. 已知局限

- 主连拼接：天勤 `KQ.m@` 自带换月处理，但不同 `adj_type` 口径会影响长周期回测的绝对收益
- 合约规格未经当日公告核验（`verified=False`），实盘前必须核对
- 单一账户口径，不建模经纪商分层、交易所限仓、强制减仓
- 不处理涨跌停无法成交的极端情形（用 volume<=0 近似跳过）
- **跨策略腿不做净额对冲（netting）**：每条腿独立开仓，trend 做多 TA 而 xsec 做空 TA 时，
  账上会同时存在两个方向相反的持仓，多付一次手续费和保证金（净敞口仍然正确）。
  这是为了归因清晰做的取舍；要省成本就得加一层「合并后统一撮合」的净额层，见 issue。
- tqsdk 3.10.x 在 Python 3.9 上有弃用警告（2027-06-01 后停止支持），建议尽快升到 3.10+

# 设计说明

## 1. 事件顺序（最重要的约定）

回测高估收益的头号原因是未来函数。本引擎把顺序写死：

```
每个交易日 t：
  ① 开盘：执行「t-1 收盘生成的目标持仓簿」，成交价 = open(t) ± 滑点
  ② 收盘：全部持仓按 close(t) 盯市
  ③ 收盘后：策略用截至 close(t) 的数据决策，生成 t+1 的目标簿
  ④ 结算：记权益快照，判定组合级回撤熔断
```

对应测试：`test_signal_fills_next_open_not_same_close`。

## 2. 期货会计口径

与股票不同，务必分清三件事：

| 概念 | 是否现金流出 | 作用 |
|---|---|---|
| 手续费 | 是 | 开平仓各收一次，平今可能加倍 |
| 保证金 | **否** | 只做「可用资金校验」，不是费用 |
| 浮动盈亏 | 否（除非平仓） | 权益 = 现金 + 浮盈 |

因此：
```
equity = cash + Σ direction × lots × (last_price − avg_price) × multiplier
```
平仓时把该笔浮盈结转进 cash，并生成 ClosedTrade。

**恒等式**（单测守着）：
```
期末权益 − 初始资金 == Σ ClosedTrade.net_pnl
```
它同时守住三件事：手续费不重复计、开仓手续费摊分正确、盯市口径一致。

## 3. 手数换算

```
日风险预算 budget = equity × target_vol / sqrt(252)
每品种预算       = budget × w_i / sqrt(Σ w_j²)
手数             = floor(每品种预算 / (ATR × multiplier))
```

为什么按 `sqrt(Σw²)` 而不是直接按 `w` 归一：等权 n 个品种时若每品种分 `budget/n`，
零相关下组合风险只有 `budget/sqrt(n)`；分 `budget/sqrt(n)` 才能用满预算。

现实里还有两个打折项：手数取整（大合约尤其严重）与品种间相关性，所以**实际波动通常低于目标**。
这不是 bug，是期货粒度与相关性的真实约束。

## 4. 成本模型

- 手续费：`max(费率 × 成交额, 固定费/手)`，平今乘倍率（股指尤其贵 → 这也是坚持日频的理由）
- 滑点：`slip_ticks × tick × multiplier × lots`，买入向上、卖出向下，永不利于策略
- 保证金：`lots × price × multiplier × margin_rate × 1.35`（1.35 模拟期货公司加收）
- 开仓前检查 `equity × 0.85 − margin_used` 是否够，不够就缩减并记拒单

## 5. 风控

| 规则 | 触发点 | 行为 |
|---|---|---|
| 单品种风险上限 | 每次换算手数 | 手数封顶 |
| 名义杠杆上限 | 生成目标簿 | 等比缩减 |
| 组合回撤熔断 | 每日结算 | 停止开新仓（仍可平仓） |
| ATR 止损 | 每日收盘 | 次日开盘平掉该品种 |
| 保证金不足 | 每次开仓 | 缩减手数 + 记拒单 |

## 6. 多策略腿（sleeve）

每条腿独立资金、独立账本、独立归因。总权益 = 各腿之和，组合级熔断对所有腿生效。
这样「按策略归因」是天然的，不需要把 PnL 分摊到策略上。

## 7. 模拟盘为什么是「确定性推进」

日频 CTA 的模拟盘本质是：每天收盘后用真实数据算一次目标，次日开盘按开盘价成交。
在数据固定的前提下，这个过程的账本是**确定性**的——它不会因为随机数而不同。

它的真实价值：
1. 验证数据管道与撮合口径（这是最容易出错的地方）
2. 积累一条**事前生成**的净值轨迹，可与后续回测对照

它拿不到的：真实盘中滑点、流动性冲击、部分成交、断线重连。这些只有实盘有。

## 8. 已知局限

- 主连拼接：天勤 `KQ.m@` 自带换月处理，但不同 `adj_type` 口径会影响长周期回测的绝对收益
- 合约规格未经当日公告核验（`verified=False`），实盘前必须核对
- 单一账户口径，不建模经纪商分层、交易所限仓、强制减仓
- 不处理涨跌停无法成交的极端情形（用 volume<=0 近似跳过）
